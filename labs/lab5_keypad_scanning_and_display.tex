\section*{Objectives}
\begin{itemize}[leftmargin=*,nosep]
  \item Understand \textbf{matrix keypad scanning} as multiplexed \emph{input} --
        the mirror image of Lab 4's multiplexed \emph{output} to a display -- and
        recognize that both need exactly 4 one-at-a-time phases, letting the
        \emph{same} four MCU pins do double duty.
  \item Wire a 4x4 matrix keypad, where every key is a dedicated \textbf{function}
        (not a digit), and a 4-digit multiplexed hex display to the Arduino Uno R3.
  \item Write AVR assembly that decodes a (row, column) key press into one of 16
        operations on two 8-bit registers, \texttt{first} and \texttt{second}, and
        applies Lecture 5's arithmetic and shift instructions to update them.
  \item Extend the provided \texttt{hex\_to\_seg} dispatcher (Lab 4-1's
        \texttt{DIGIT\_TO\_SEG} idea, grown to \texttt{A-F}) into a full 4-phase
        multiplexed refresh loop showing \texttt{first} and \texttt{second} as two
        2-digit hex bytes.
  \item Debounce keypresses and give \texttt{first}/\texttt{second} well-defined
        starting values \emph{before} any arithmetic runs, by dialing them up from
        \texttt{0x00} with the increment/decrement keys.
\end{itemize}

\begin{summary}[Quick Reference: Digit-Select \& Row Scan via DDR Toggle]
\texttt{PB2-PB5} do two jobs with \emph{one} identical trick, not two opposite
ones: toggle the pin's \textbf{direction} (\texttt{DDR}) and leave its
\texttt{PORT} bit permanently \texttt{0}.
\begin{itemize}[nosep,leftmargin=*]
  \item \textbf{Input} (\texttt{DDR} bit \texttt{= 0}): the pin floats
        (high-impedance). A digit's cathode then has no path to ground, so it's
        dark, \emph{and} that row is not being driven, so a key pressed on it
        can't pull any column low. Both effects are ``off,'' for free.
  \item \textbf{Output} (\texttt{DDR} bit \texttt{= 1}, \texttt{PORT} bit
        \texttt{= 0}): the pin actively sinks to \textbf{GND}. The digit's
        cathode is grounded, so whatever pattern is already on the segment bus
        lights up, \emph{and} that row is driven low, so a pressed key on it
        pulls its column low. Both effects are ``on,'' together, from one
        \texttt{SBI}/\texttt{CBI DDRB,}$n$.
\end{itemize}
Per phase $i$ (pin \texttt{PB}$(2{+}i)$): write digit $i$'s hex pattern to the
segment bus \emph{first}, then \texttt{SBI DDRB,}$(2{+}i)$ (digit lights up
already correct, no blank/stale flash), poll \texttt{PINC} once for row $i$'s
keys, hold for $t_{\text{dwell}}$, then \texttt{CBI DDRB,}$(2{+}i)$ before moving
to phase $i{+}1$. \texttt{SBI}/\texttt{CBI} need a compile-time constant bit
number, so this is written as 4 explicit unrolled blocks, not a loop indexed by
a register -- see the Starter Code below.
\end{summary}

\begin{summary}[Quick Reference: How Matrix Scanning Works]
A 4x4 keypad packs 16 keys into just 8 wires -- 4 rows + 4 columns -- because each
key does nothing but bridge \emph{one} row wire to \emph{one} column wire when
pressed; there is no other connection inside the keypad. Driving all 4 rows at once
would make every key on a pressed column look identical, so scanning removes the
ambiguity: drive exactly \emph{one} row \textbf{LOW} (the other three stay
floating/inactive), read all 4 columns, and only trust what you read while that
one row is the low one. Cycle through all 4 rows, fast enough that a keypress
during any row's turn gets caught.
\end{summary}

``inc inc'' / ``dec dec'' means \emph{call the increment/decrement routine twice},
not a separate \texttt{+2} instruction -- reusing \texttt{R1}'s single-step
routine is the point. All eight arithmetic keys (\texttt{R3-R4}) are ordinary
8-bit AVR ops: \texttt{first}/\texttt{second} wrap silently on overflow/underflow
(mod 256) exactly as \texttt{ADD}/\texttt{SUB} leave them, with the \texttt{C} flag
recording what wrapped -- see Exercise 5 and the take-home Trace problem.

The four rows split into two structurally different kinds of key. \texttt{R1-R2}
are \textbf{single-register} ops -- each key touches only \texttt{first} \emph{or}
only \texttt{second}, never both, so they're the only keys that make sense on a
freshly-reset board where both registers are still \texttt{0x00}. \texttt{R3-R4}
are \textbf{combining} ops -- every one reads \emph{both} registers to update one
of them (a shift by the other register's amount, or an add/subtract between the
two), so they only do something meaningful once both already hold real values.
That split is exactly why Exercise 3 (input phase) uses only \texttt{R1-R2}, and
Exercise 4 (dispatch table) is where \texttt{R3-R4} first do anything.
\end{summary}

\begin{summary}[Quick Reference: Current Budget -- Why No Transistors Here, and the Catch]
Lab 4-1 used an NPN transistor per digit specifically so the AVR pin only ever
sources the transistor's small \textbf{base} current, not the segments'
combined current. This lab's reference board skips that stage: \texttt{PB2-PB5}
sink each digit's cathode \emph{directly}. That works electrically, but it
removes Lab 4-1's safety margin -- check it before you trust it.
\[
I_{\text{segment}} = \frac{V_{CC} - V_{LED}}{R} \approx \frac{5\text{V} -
2\text{V}}{330\Omega} \approx 9.1\text{ mA}, \qquad
I_{\text{digit (worst case)}} = 7 \times I_{\text{segment}} \approx 64\text{ mA}
\]
Digit \texttt{8} lights all 7 segments at once, so its digit-select pin
momentarily sinks $\approx$64~mA -- \emph{above} the ATmega328P's 40~mA
absolute-maximum per-pin rating, even though it's only for one
$t_{\text{dwell}}$ at a time. Many boards survive this in practice (real parts
have margin beyond their datasheet limits), but it is out-of-spec, not a safe
design. Before wiring your board, decide: increase the segment resistors
(e.g.\ 330$\Omega\to$1k$\Omega$ cuts $I_{\text{digit}}$ to $\approx$21~mA, back
under the limit, at the cost of a dimmer display), or reintroduce Lab 4-1's
transistor stage on \texttt{PB2-PB5}. Either choice is acceptable for this lab
-- record which you picked and why.
\end{summary}

\begin{summary}[Quick Reference: Multiplexing and Refresh Rate]
Only \emph{one} digit's common cathode is ever grounded at a time. Show each digit
for a short \textbf{dwell time} $t_{\text{dwell}}$, then switch to the next --
fast enough that the eye's flicker-fusion threshold ($\approx$50-60~Hz) blends all
four into one steady image:
\[
f_{\text{refresh}} = \frac{1}{N_{\text{digits}} \times t_{\text{dwell}}}, \qquad
N_{\text{digits}} = 4 \ \Rightarrow\ t_{\text{dwell}} \le \frac{1}{4 \times 60\text{Hz}}
\approx 4.17\text{ ms}
\]
This bound is \emph{tighter} than Lab 4-1's 2-digit bound (8.3~ms) -- twice as many
digits means half the time budget per digit for the same refresh rate. Recompute
$f_{\text{refresh}}$ for your own $t_{\text{dwell}}$ below and confirm you're still
comfortably clear of 60~Hz.
\end{summary}

\section*{Building the Circuit}
\begin{enumerate}[leftmargin=*,nosep]
  \item \textbf{Rows.} Wire keypad \texttt{R1-R4} to \texttt{PB2-PB5} (Uno
        D10-D13) -- the \emph{same} four pins as digit-select (step 4).
  \item \textbf{Columns.} Wire keypad \texttt{C1-C4} to \texttt{PC0-PC3} (Uno
        A0-A3). These are \textbf{inputs} with the AVR's internal pull-up enabled
        -- no external resistor.
  \item \textbf{Segment bus.} For all 4 digits, tie \emph{every} digit's
        same-lettered segment pin together (module pins \texttt{A,B,C,D,E,F,G} --
        Display Module Pinout box), then run that shared node through one
        330~$\Omega$ (or 1~k$\Omega$) resistor to the matching MCU pin
        (\texttt{a}(11)$\to$\texttt{PB1}, \texttt{f}(10)$\to$\texttt{PB0},
        \texttt{b}(7)$\to$\texttt{PD2}, \texttt{c}(3)$\to$\texttt{PD3},
        \texttt{d}(2)$\to$\texttt{PD5}, \texttt{e}(1)$\to$\texttt{PD6},
        \texttt{g}(4)$\to$\texttt{PD7}). 7 resistors and 7 MCU pins drive all 4
        digits, not 28.
  \item \textbf{Digit-select.} Module pin \texttt{D1} (pin 12, leftmost digit)
        goes \emph{directly} to \texttt{PB2}, \texttt{D2} (pin 9) to
        \texttt{PB3}, \texttt{D3} (pin 8) to \texttt{PB4}, \texttt{D4} (pin 5,
        rightmost) to \texttt{PB5} -- the \emph{same} four pins used for keypad
        rows \texttt{R1-R4}. No transistor, unless you chose that option in the
        Current Budget box, in which case wire it exactly as Lab 4-1 did
        (cathode $\to$ collector, emitter $\to$ GND, base $\to$ 1~k$\Omega$
        $\to$ \texttt{PB}$(2{+}i)$).
        Double-check each \texttt{PB}$(2{+}i)$ node really does connect to
        \emph{both} the keypad row \emph{and} the digit's cathode -- this is
        the one wiring step that differs from Lab 4-1.
\end{enumerate}

\section*{Provided Starter Code}
The skeleton below is given: the one-time setup, the \texttt{hex\_to\_seg}
pattern (shown for digits \texttt{0}-\texttt{1} -- finishing the rest is
Pre-Lab Task 1, next section), \texttt{Delay1ms}, and the 4-phase
\texttt{REFRESH} loop's shape. Everything marked \texttt{TODO} is deliberately
unfinished, in three stages: stashing/decoding the column poll into a
\texttt{key\_index} is Pre-Lab Task 2 (also next section, \emph{before} this
lab session); debouncing it is Exercise 2; dispatching it to an actual
operation on \texttt{first}/\texttt{second} is Exercise 4 -- the two pieces
that are mostly mechanical (getting every segment code right, getting a
reliable 16-key decode) are pushed to homework, so lab time goes to the
arithmetic that's this lab's actual point.

\begin{lstlisting}[style=asm]
; ---- one-time setup: segment pins are ALWAYS outputs, never re-cleared ----
sbi   DDRB, 0          ; PB0 = seg f
sbi   DDRB, 1          ; PB1 = seg a
sbi   DDRD, 2          ; PD2 = seg b
sbi   DDRD, 3          ; PD3 = seg c
sbi   DDRD, 5          ; PD5 = seg d
sbi   DDRD, 6          ; PD6 = seg e
sbi   DDRD, 7          ; PD7 = seg g
; PB2-PB5 (digit-select / rows) start as INPUTS (the AVR reset default) --
; do NOT set their DDR bits here; each refresh phase below toggles just its
; own bit, on the way in and back out.
cbi   DDRC, 0          ; PC0-PC3 = keypad columns, input
cbi   DDRC, 1
cbi   DDRC, 2
cbi   DDRC, 3
sbi   PORTC, 0         ; internal pull-ups on
sbi   PORTC, 1
sbi   PORTC, 2
sbi   PORTC, 3

; ---- hex_to_seg: r17 (0x0-0xF) in, segment bus written, r17 clobbered ----
; Same CPI/BRNE-chain idea as Lab 4-1's DIGIT_TO_SEG; 0-9 identical, A-F new.
hex_to_seg:
    cpi   r17, 0x0
    brne  hts_1
    sbi   PORTB, 1      ; a
    sbi   PORTD, 2      ; b
    sbi   PORTD, 3      ; c
    sbi   PORTD, 5      ; d
    sbi   PORTD, 6      ; e
    sbi   PORTB, 0      ; f
    cbi   PORTD, 7      ; g
    ret
hts_1:
    cpi   r17, 0x1
    brne  hts_2
    cbi   PORTB, 1
    sbi   PORTD, 2
    sbi   PORTD, 3
    cbi   PORTD, 5
    cbi   PORTD, 6
    cbi   PORTB, 0
    cbi   PORTD, 7
    ret
hts_2:
    ; ... continue the same pattern for 2-9 ...
    ; then A, b, C, d, E, F using the Hex Segment Codes table above
    ret

; ---- one-time delay tick (~1ms at 16MHz); call it N times for N ms ----
Delay1ms:
    ldi   r18, 21
dl1: ldi  r19, 25
dl2: dec  r19
     brne dl2
     dec  r18
     brne dl1
     ret

; ---- REFRESH: 4 unrolled phases (SBI/CBI need a compile-time bit number, ----
; ---- so this can't be a loop indexed by a register -- see the box above) ----
; r21 = first (0x00-0xFF), r22 = second (0x00-0xFF)
REFRESH:
    ; ---- Phase 1: first's high nibble, row R1 ----
    mov   r17, r21
    swap  r17           ; one instruction instead of four LSLs/LSRs
    andi  r17, 0x0F
    rcall hex_to_seg
    sbi   DDRB, 2        ; DIGIT1 on, ROW1 driven low
    in    r16, PINC      ; poll C1-C4 for row 1
    ; TODO (Pre-Lab Task 2): mask to bits 0-3, compare against 0x0F (the
    ; "no key in this row" sentinel), and if not equal, fold row+column into
    ; a single key_index (0-15) and stash it.
    rcall Delay1ms        ; repeat/scale to your t_dwell
    cbi   DDRB, 2        ; DIGIT1 off, ROW1 floats

    ; ---- Phase 2: first's low nibble, row R2 ----
    mov   r17, r21
    andi  r17, 0x0F
    rcall hex_to_seg
    sbi   DDRB, 3
    in    r16, PINC      ; row 2
    rcall Delay1ms
    cbi   DDRB, 3

    ; ---- Phase 3: second's high nibble, row R3 ----
    mov   r17, r22
    swap  r17
    andi  r17, 0x0F
    rcall hex_to_seg
    sbi   DDRB, 4
    in    r16, PINC      ; row 3
    rcall Delay1ms
    cbi   DDRB, 4

    ; ---- Phase 4: second's low nibble, row R4 ----
    mov   r17, r22
    andi  r17, 0x0F
    rcall hex_to_seg
    sbi   DDRB, 5
    in    r16, PINC      ; row 4
    rcall Delay1ms
    cbi   DDRB, 5

    ; TODO (Exercise 2): debounce key_index against t_debounce.
    ; TODO (Exercise 4): dispatch key_index to one of the 16 functions
    ; (Function Key Map) and update r21/r22 accordingly.

    rjmp  REFRESH
\end{lstlisting}

\medskip\textbf{Critical check -- verify, don't just accept:}
Before trusting any AI-suggested segment resistor value, check it against your

answer assumes a specific LED forward voltage that may not match your display's
actual datasheet.

\medskip\textbf{Know the limit:}
AI tools asked to ``share a GPIO pin between two peripherals'' will often default
to a diode-OR or an external mux/decoder chip, without noticing when a much
cheaper option exists: two peripherals whose \emph{idle} state is passively safe
(floating and driven-low, in this lab's case) can just share the pin directly, as
long as you can tolerate their features being mutually exclusive in time. Ask
specifically whether your two signals' idle behavior is passively safe before
reaching for extra hardware.
\end{aicollab}
